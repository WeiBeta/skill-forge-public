# 管理协议范本

初始化时裁剪角色和字段，指定唯一主控、权威台账与领域入口。适用于多任务工程；单步任务可直接完成并记录必要结果。

## 状态与任务

[CURRENT](../management/CURRENT.md)只更新发生变化的目标、权限或暂停、活动任务、责任和下一依赖；[TODO](../management/TODO.md)只列实际未完成项。事实在现有专项记录或[LEDGER](../management/LEDGER.md)记一次，用稳定ID与固定对象引用。日常续接查活动项；按实质交接、具体矛盾或明确要求才校对，留核对截点，并发回执先核再合并。历史失败和暂停保留当时状态，现行入口用当前适用裁定。

派前冻结任务ID、目标和验收、必要输入、实际执行根和允许写入范围、路由及回执目标。只有影响验收、保全或权限时，才逐项列出精确文件、哈希、共享资源、预算和停止线。区分用户边界、工具许可与管理检查点；模板不授予权限，也不追改在途工单。

结果按事件记录：拟定→已派发→执行/阻断→候选→审查/核收→关闭。状态说明具体对象；CandidateNotRun、Failed、Unknown和NotRun保留。写账失败时先保留最小恢复记录，停止依赖其状态的后续，不凭聊天记忆重跑副作用。

## 完整工作包与验证

同一执行者完成实现、自测、采集和收尾。先看实际失效后果，用下表决定验证；文件数、提交数及模型给出的严重度不决定等级。

| 等级 | 何时适用 | 交付与验收 |
| --- | --- | --- |
| T3 | 变更公开导出、权限、发布或灾备机制，或涉及不可逆数据变更 | 用正常操作或配置失误可达的样例验证边界与恢复，交一位实现外审查者。实际泄露、数据丢失或静默产出坏包须修正。 |
| T2 | 运行期行为、跨模块契约、路由目标或调用契约发生变化，或自用及通用规则改变了实际职责和审查要求 | 按具体失效面补测；涉及多方使用或高影响时，由一位实现外审查者核相关差额。 |
| T1 | 其余局部可逆且可独立核验的改动，如措辞、仍指向同一权威的链接或解析到同一目标且调用契约不变的 ID 修正 | 同包分析、实现、自验；主控核差异和受影响的实际入口。无需专用工作树或正式独审。 |

有真实灰区时，两句话说明分歧与后果交主控裁定。执行者把兼容样本、难复现故障和里程碑基线保存在原工单；普通成功日志随运行产物。业务结果已存在而采集失败时，复用结果、补缺失证据，保留原异常。新提交可复用已有证据覆盖的行为，新增风险只审其差额。

## 协调与并发

主控作工程决定并核收；PM执行冻结的派工/续接/结果汇总，默认只检查回执完整性。轻型工具可由同一执行者直接交付并自验；追加PM应有隔离职责，不能形成两个权威台账写入者。

当派工、核收或阻断改变下一步时，一次核清必要输入、实际实例与执行根、读写集、Git index/ref、共享缓存/输出/进程及独占资源。只串行实际冲突；集成单写。汇合前核实际组合的基线、交叉改动和必要验证。换模型、供应商或工具不扩大授权。

原生子代理回直接父，其他执行者按实际通道取结果。PM 按每单及约定阶段的完成、失败、阻断或需裁决给主控一次实质回执。用任务、阶段、候选及终态去重；重复消息不触发重新派工或执行。Bridge 逐单报告已知终态，当前已就绪的可同发；固定批次的汇合与验收不扣住逐单回执。其他通道明确约定的批次合收按原工单，新单不拖延旧单。

### PM 初始化与接收

按实际任务通道初始化 PM：`gpt-native`、`third-party-subagent` 或 `agent-bridge`。由项目已安装的 pm-management 维护接收合同，work-dispatch 消费。新建或轮换时分别核对实际沙箱与审批方式；项目约定手调权限时由作者明确就绪。未装技能时，先在现有记录固定角色与授权、项目根、各单路由、真实工具和身份、主控通知渠道、累计预算/截止、终态采集与停止交接；无可靠接收和交接路径不启用受影响的派工。复用或轮换不修改旧单合同。

主控只等独立 PM 时按已验证通知机制结束回合，没有可靠续接就留下人工入口；不接管其接收循环。原生直接父（包括获准直派的主控）保持接收回合，用支持的事件或直接等待。第三方原生子任务无适用事件时，只按授权对具体任务做低频有界等待或必要精确确认；Bridge PM 在同一活动回合用派单的协调器和任务 ID 拉取结果，并行或在已知任务间公平轮转。Bridge 每次外层调用只开一个有界窗口，窗口内可并收独立任务。返回 PM 后先处理暂停或插单，再以各单原截止与余额决定续收。模型名不能证明协议能力，落盘结果或回合内事件不能证明会唤醒已结束回合。

在途换岗先由具名接手方确认原任务的接收权与剩余预算；原生子事件只交直接父会话。无接手条件时原持有者在获准范围内收尾，到限或暂停则保留任务、责任与人工恢复入口。当前暂停限制优先于旧合同；只按暂停指令明确允许的动作在原预算内自然收口。截止时只做仍获准且预留的一次非阻塞精确确认；预算耗尽或无合法窗口就交接。保留未终态、已用额度及其可恢复记录、原截止、身份和恢复入口；余额不明则停依赖该余额的动作。timeout 不作任务终态，新任务不延长旧单期限。未知是否启动不重派，截止不自动取消业务。不得用列表轮询、空 ACK、定时器或无界后台循环保活。

## 核收与恢复

回执至少含任务/实例、候选或无写入、终态/异常、已消费预算、资源/关闭、需裁决及证据指针。标明执行者报告、PM实查或主控验收。范围偏差不能淡化成普通保留项；失败后成功仍保留原事件。

主控按风险核对象与关键证据，正式Review使用实现外实例。工具受理不等于执行，单项测试通过不等于父目标完成；核收后入账，再放行依赖后续。

先区分通信、工具、业务与采集失败，核已发生动作；可补采则复用结果，确定性错误先在包内局部纠正。仅有已知瞬态原因、可安全重复且原合同允许时才原样重试。通信、服务、入口尝试和业务启动按各自预算累计，跨回合、换实例和内部重试不重置。拒绝即停对应操作；Unknown 只停依赖它的部分，真实启动不明时不重放。暂停时留安全断点与资源归属，不强杀代替回执。

共享目录变更列表只作线索，归责或回滚前核具体写入。轮换或关机时查明迟到回执的实际收件人，旧岗无在途责任即可交接。阶段结束保留固定输入、产物、失败与未测、活动资源、下一门禁。代理close与工作树/文件可删除分别裁定；清理需核归属、保全和实际删除授权。
