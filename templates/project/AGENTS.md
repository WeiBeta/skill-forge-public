# 项目工程协作总纲

本文件是待项目维护者裁剪的范本，不携带神机百炼或其客户的授权。首次采用先明确本项目目标、主控和领域真源，再启用所需角色。

- 用户目标、暂停与明确授权优先；分析不等于实施，工具可调用不等于业务获准。保留失败、未知与原始证据。
- 日常恢复先读[CURRENT](management/CURRENT.md)的活动项和下一依赖，按需查[TODO](management/TODO.md)及固定证据。首次接管或规则无法局部确认时读完整[管理协议](docs/MANAGEMENT.md)；执行者只读工单冻结的适用条款。
- 职责按需读：[主控](docs/roles/controller.md)、[PM](docs/roles/pm.md)、[执行](docs/roles/executor.md)、[独立审查](docs/roles/reviewer.md)。未配置角色不自动创建；正式独立审查不能由实现者自检替代。
- 客户领域合同与工程约束分别维护。主控在项目选型表区分常规与显式赶工，绑定已启用的执行通道。每个需正式审查的工单只配一位实现外审查者。既有真源优先，角色/模型/窗口等动态配置放现势记录，不在各份规则复制。
- 创建、复用或轮换 PM 使用项目实际安装的 pm-management；日常派发、续接与核收使用 work-dispatch，并引用已就绪的接收合同。技能缺失按[管理协议](docs/MANAGEMENT.md#pm-初始化与接收)裁剪，不自动安装。
- 原生代理模型服务瞬态故障按已安装的agent-recovery处理；明确要求台账校对或证据冲突时按ledger-reconcile处理。仅在对应触发时读取，保持本项目授权、累计预算及唯一主账写入责任。
- 主控负责核收并单写权威台账，PM协调。按失效后果确定 T1、T2 或 T3，默认交[完整工作包](docs/MANAGEMENT.md#完整工作包与验证)；执行者在边界内决定普通实现、自测与证据采集。实例、工作树和共享资源分别核隔离。
- 已授权且可隔离的工作连续推进。主控只接独立 PM 的实质回执；只剩该依赖时保存断点。PM 按就绪合同接收具体任务，主控获准原生直派时按直接父职责接收，见[管理协议](docs/MANAGEMENT.md#pm-初始化与接收)。
- 变更前核现场差异，保留无关修改；删除、外发、发布及共享配置变更核实际目标和适用授权。秘密不进日志/仓库，备份存在不是删除授权。
- 完成、测试通过、采集完整、部署、加载、业务验收、代理关闭及恢复演练分别陈述。验证按风险选择，固定输入/次数/停止线不因换树或换模型重置。
