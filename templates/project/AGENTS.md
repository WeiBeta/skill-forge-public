# 项目工程协作总纲

本文件是待项目维护者裁剪的范本，不携带神机百炼或其客户的授权。首次采用先明确本项目目标、主控和领域真源，再启用所需角色。

- 用户目标、暂停与明确授权优先；分析不等于实施，工具可调用不等于业务获准。保留失败、未知与原始证据。
- 管理恢复读[CURRENT](management/CURRENT.md)、[TODO](management/TODO.md)；接管、首次派工或治理变化再读[管理协议](docs/MANAGEMENT.md)。执行者只读冻结工单及适用条款，不恢复全部历史。
- 职责按需读：[主控](docs/roles/controller.md)、[PM](docs/roles/pm.md)、[执行](docs/roles/executor.md)、[独立审查](docs/roles/reviewer.md)。未配置角色不自动创建；正式独立审查不能由实现者自检替代。
- 客户领域合同与工程约束分别维护。既有真源优先，角色/模型/窗口等动态配置放现势记录，不在各份规则复制。
- 多任务派工与核收使用已安装且适用的work-dispatch技能；未安装时按管理协议处理，不凭技能名称安装外部包。
- 主控唯一维护权威台账与验收；PM协调，执行者在工单写集内工作。独立聊天或Agent不证明工作树隔离；共享Git状态、集成及独占资源不得并发写。
- 已授权且可隔离的工作连续推进；依赖回执时用宿主支持的事件机制，不轮询、空ACK或定时唤醒。新任务不延长旧固定批次的回执条件。
- 变更前核现场差异，保留无关修改；删除、外发、发布及共享配置变更核实际目标和适用授权。秘密不进日志/仓库，备份存在不是删除授权。
- 完成、测试通过、采集完整、部署、加载、业务验收、代理关闭及恢复演练分别陈述。验证按风险选择，固定输入/次数/停止线不因换树或换模型重置。
