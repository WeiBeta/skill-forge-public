# 工单与回执的最小信息

仅在需要编制或检查结构时读取；字段随任务风险裁剪，不让普通小改强制建多层工单。

## 工单

任务ID；目标与验收；本次适用授权；固定输入commit/文件哈希；实际执行根与允许写集；角色/模型/档位；依赖、共享资源和汇合条件；动态或外部副作用预算；停止线；回执目标。若某项不适用写原因，不猜默认额度。

示例：任务T-12修订固定候选的解析器，根为主控指定的隔离树A，仅允许解析器和对应测试两文件；测试使用已有本地夹具，外部调用0。T-13只读检查独立文档，不写A。T-12候选固定后才做实现外Review；两者无需等齐才分别回执。

## 回执

- 任务/实例与候选提交，或明确无写入。
- 实际结果、失败/范围偏差、未验证项。
- 已消费预算和副作用状态。
- 资源与close证据，未知分别保留。
- 事实来源：执行者报告 / 协调者实查 / 主控验收。
- 固定证据指针、需裁决项和下一依赖。

不要重复复制全过程或手算源计数。消息接受不是主控已经核收，脚本退出成功不是业务验收；暂停回执仍须保留现场与后继入口。
