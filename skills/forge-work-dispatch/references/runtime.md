# 按能力适配宿主

首次适配、接口变化、冷启动误用或实际故障时读取。通用派工不要求OpenCodex或固定模型供应商。

| 能力 | 核实什么 |
| --- | --- |
| 创建/路由 | 原生子代理与独立聊天分别处理；显式参数、受理、自报、服务身份分列 |
| 隔离 | 分别核实例身份、实际工作目录与 Git 根、index/ref、共享缓存/输出/进程及独占工具；创建成功不等于已分配树 |
| 等待 | 当前工具族、直接事件等待、外层让出、父回合是否仍活跃 |
| 消息 | 已授权目标、终态分项回执、去重；已结束父回合是否能被消息唤醒 |
| 权限 | 当前实际限制；父配置和角色说明不能代证子执行权限 |
| 关闭 | completed、公开close、资源释放分别有证据；缺接口不猜替代命令 |
| 恢复 | 本项目预算、幂等性、副作用；通信/服务/业务次数分开 |

原生Codex与Codex＋OpenCodex是不同适配路线。原生路线按目标版本核实际V2能力；OpenCodex路线只参考已核版本/组合。V1/V2参数和恢复动作不互套；不要把V2等待参数当第三方V1也已零空转。其他harness或路由按能力自行适配，未经验证不继承效果结论。

路径长度等环境约束按实际需要核对；绑定条件不变时引用已有证据，只重核变化影响的路径。换宿主、会话或模型先保存安全断点、已用预算和活资源归属。新实例不自动继承权限、次数或进程。没有适用的恢复接口、授权或预算时，保留现场并报告受影响的依赖。

如本项目另有明确授权，可把同一瞬态操作的累计尝试上限定为三次（含首次及内部重试）。消息投递可另定最多三次发送、三次有界核查（均含首次）；仅因实际失败或漏回执核查，取得所需结论即停。此为预算写法示例；更窄的专项上限优先，不增业务启动次数，也不改变拒绝停止。

工具外层反复续等可能触发父模型请求；零空转须用真实请求记录验证，不能凭配置或正常等待表象宣称。模型总用量不等于协调浪费，缓存输入不得重复计入。普通任务不重跑性能/权限探针。

## 三条接收路径

| 接收者与依赖 | 当下动作 | 何时结束或交接 |
| --- | --- | --- |
| 主控等独立PM消息 | 先做其他输入齐备的获准工作；只剩外部依赖就保存断点 | 按已验证实质消息机制结束；未证可靠续接则留人工入口，不查询PM列表保活 |
| 直接父会话等原生子（含获准直派的主控） | 绑定具体子ID/turn及实际工具族，在接收回合内消费事件或直接等待 | PM终态后核最低完整性、逐单实质回主控；主控直派按自身职责核收，再按剩余子项决定；不能因“只等结果”提前final |
| 无适用事件的获准适配 | 按工单累计预算做低频等待及必要精确确认；不同等待包装层分别记 | 超时仍非终态；耗尽或无合法调用区间报告未终态与恢复入口，停止追加等待/确认，不取消业务或自行续额 |

`await`挂起/外层让出表示工具仍待返回；timeout表示本次等待返回；assistant final/completed表示父回合已结束；新turn启动是另一个事实。一次回合内等待成功不能证明子事件会开启已结束父回合。子任务未终态的预算交接也不能标成任务完成，后续沿已验证消息或人工入口继续。

所有等待路径共用停止线：适用预算耗尽或无合法调用区间时，保存未终态、已用预算和恢复入口，同时停止追加等待/确认，不自行续额、重派或取消业务。仅剩子结果不是提前final的理由；停止线触发时仍交接收口。等待预算应明确累计时长/次数中实际采用的上限、消费记录及停止线；有限等待不意味着可以随超时无限续期。参数须同时符合当前schema和上层时限，不能借外层长等或短轮询绕开。notLoaded、列表消失、文件已存在不能替代终态或close证据。协调等待与429/502原实例恢复是不同操作，不能借用恢复次数作为无限续等许可。

## 采用与核验示例

- 冷启动规则“只等外部结果就结束”若没有接收者限定，会误用于直接父会话。应先读三条路径；已安装技能有正确区分时，记录为入口/采用缺陷，不能倒写成旧技能要求错误。
- 同回合等待与跨已结束回合唤醒是不同证据；等待包装器可能触发父请求。应按实际工具协议、调用记录和当前时限判断兼容性与成本，不能将一种组合的观察推广到所有环境。
- 模型家族不是协议证据。GPT样本只见等待摘要、未见完整工具族时，保留V1/V2 Unknown；第三方PM走V1也不能推定所有第三方都不兼容V2。普通业务不为填Unknown重开实验。
- PM默认核身份、目标、字段、异常、预算与资源；现有执行日志足够时不重跑全部测试。通过、跳过与失败数量应从实际汇总取值；修正错误摘要保留原记录，不为重计数重跑业务。
