# 按能力适配宿主

新环境、接口变化或实际故障时读取。通用派工不要求OpenCodex或固定模型供应商。

| 能力 | 核实什么 |
| --- | --- |
| 创建/路由 | 原生子代理与独立聊天分别处理；显式参数、受理、自报、服务身份分列 |
| 隔离 | 实际workdir、Git根、共享index/ref、独占资源；创建成功不等于已分配树 |
| 等待 | 当前工具族、直接事件等待、外层让出、父回合是否仍活跃 |
| 消息 | 已授权目标、终态分项回执、去重；已结束父回合是否能被消息唤醒 |
| 权限 | 当前实际限制；父配置和角色说明不能代证子执行权限 |
| 关闭 | completed、公开close、资源释放分别有证据；缺接口不猜替代命令 |
| 恢复 | 本项目预算、幂等性、副作用；通信/服务/业务次数分开 |

原生Codex与Codex＋OpenCodex是不同适配路线。原生路线按目标版本核实际V2能力；OpenCodex路线只参考已核版本/组合。V1/V2参数和恢复动作不互套；不要把V2等待参数当第三方V1也已零空转。其他harness或路由按能力自行适配，未经验证不继承效果结论。

工具外层反复续等可能触发父模型请求；零空转须用真实请求记录验证，不能凭配置或正常等待表象宣称。模型总用量不等于协调浪费，缓存输入不得重复计入。普通任务不重跑性能/权限探针。
