# 分层诊断

固定入口、候选、精确症状和适用合同，先读最近相关原始证据。分别判断进程是否创建、输出是否捕获、环境是否可用、业务执行到哪里、证据是否封存、核验器怎样解释。超时或捕获失败不证明业务未发生；收集失败不等于测试体失败。

选择能区分假说的最小检查：已有材料对照、离线回放、合成正负例或单一合同断言。结构化输入先查实际消费者 schema/真实样例与晚生成身份的注入时机；候选副本可能串源时才核实际导入来源。入口稳定且只变参数时，核绑定、实际范围和输出；参数传递、捕获或退出语义变更才核相应控制路径。不要凭自然语言猜接口或因包装器报错先重装环境。

原始输出不保证 UTF8。解码失败保留 bytes、长度与哈希，解码视图另存，不猜编码后覆盖原件。涉及证据转换时区分生产者事实、传输/接收转换和校验规则，保留旧红灯，不放宽业务合同换绿。

测量异常时先确认量尺：单位、线程、采样边界及已知工作量正对照。资格、样本覆盖和业务判定各自绑定环境；零读数不证明零分配，某宿主有效不能给另一个宿主背书。

无安全复现条件仍可给有依据的未验证假说，说明预测、缺失观察与最小反证；不强制先造红灯或百次循环。捕获失败先核是否能恢复已有结果，只修出错环节。执行前检查副作用、预算和暂停；入口尝试和真实业务启动按原合同分别记。启动不明时，不能为补证重放真实调用。独立安全离线分析可继续。

结论列已证事实、假说、反证、影响及下一安全动作。Unknown 只阻断依赖项；保留有效局部结果。核验器改动采用独立正负例，不沿被测实现同法计算期望。读[诊断案例](references/cases.md)处理串源、输入适配或计量故障；来源见[归属](references/attribution.md)。
