# 双轴审查

先固定实际待审对象和适用合同。代码审查绑定 repo/base/候选提交，dirty 内容补文件哈希或补丁；部署或构建审查再核对应产物身份。普通文本固定文件即可，不凑无关构建字段。已有冻结材料直接引用，不追随活动源码。

- **规格轴**：检查需求、领域边界、禁止范围及遗漏；定位真实规范与消费者，不靠文件名猜合同。缺规格时明确覆盖缺口。
- **质量与证据轴**：检查错误与资源生命周期、兼容职责、公共行为、独立预期及证据来源。控制完成、业务结果、计量资格和管理接纳分别判断；Unknown 只限制依赖它的结论，不抹掉独立成立的局部事实。

每条 finding 都核对候选中的符号/引用是否真实、触发路径是否可达、违反哪个合同及实际影响；报告位置、最窄验证和未证部分。格式齐全或模型给出高严重度不能代替这些核查；抽样说明分母，不外推全库。重复和转发层只是维护线索，不据此删除承担兼容或隔离的 adapter。

把差异映射到证据：保留哪些旧结论，失效哪些绑定或行为，补证为何必要。各修订链单独通过不等于最终组合通过；局部变化也不自动触发全量重测。字节交付、过滤器或运输影响结论时，才核需要的物理字节、Git index/blob 及转换；候选可能串源时检查同一测试进程的实际模块来源。

独立审查已验证精确修正时，可在复核适用基线、实际改动、组合影响及必要回归后引用原审查。审查建议、相近行号或改动后换 SHA 都不能证明覆盖；若出现新风险或超出覆盖，补审受影响部分。

两轴分别报告结论、覆盖和未测，嵌入既有 Review。正式独立审查由未参与实现者以最小固定输入、干净上下文进行；原实现会话换模型不构成独立性。小改不固定双代理或增加审查层。

遇到疑似虚构 finding、候选串源或脆弱测试，读[审查案例](references/cases.md)。来源与许可见[归属](references/attribution.md)。
