# 原实例有界续接

1. 确认错误来自原生代理模型服务层，且属于已观察到的瞬时429/502或已明确分类为同类的失败。业务HTTP错误、负向测试、额度耗尽、模型容量不足、权限/策略拒绝、用户暂停和普通工具失败不进入本流程；429本身不证明配额或网络根因。

2. PM核原任务仍有效、未完成/暂停/关闭，原实例可按稳定标识定位，固定工单可核验。查同工单累计自主续接计数n；默认上限3次，已冻结工单或客户更严格限制优先。只有n已知且未达适用上限才继续；未知先查缺口，不能默认为0。更换措辞、shell、工具入口、PM或重新进入技能不重置计数；原任务首次调用不计为恢复尝试，工具内部重试另记，不据此虚构新增可用次数。

3. 在原任务记录保存错误证据、已完成动作、活进程、可能副作用、最晚安全断点、激活计数及实际工具。未明确的执行保留Unknown。没有可安全续接的断点时交管理裁定，不重放副作用不明的命令。

4. 核当轮暴露的正式原生代理消息工具及真实参数，目标只能是原实例；不猜接口，不用普通会话消息替代。工具缺失或接口不符时报告该依赖缺口。不增加模型/档位/interrupt覆盖，不新建实例、不换模型/供应商/账号、不改权限、不强杀进程。

5. 在发送前持久登记本次尝试n→n+1及适用上限，再发送短续接消息：绑定原工单；保持原写入范围、模型、权限和累计预算；先核实际执行记录与副作用；从未完成的安全断点续作；已经执行或副作用不明的动作不得重放；完成/失败/阻断时回一次实质结果。发送中断或结果未知也计入已尝试；未查清前不再次发送，没有工具受理证据不能推定请求未发生。

6. 分别登记请求结果、实际恢复及正式完成。受理不等于恢复。只有收到新的、已明确分类的同类瞬态失败事件，且前次结果与副作用已核清，才返回步骤1判断下一次；成功后不补满次数。拒绝、暂停、结果不明或无法安全续接立即停止并回执主控，不等待耗尽。达到3/3（或适用的更低上限）仍失败时，PM提交错误、累计次数、完成部分、安全断点及待裁决事项，由主控决策；不得自主第4次、重置计数、新建替代实例或切换供应商。原任务动态次数、业务预算和停止线保持，不以续接次数替代业务额度。不得轮询、定时等待、空ACK、额外权限探针或外部通知保活。
