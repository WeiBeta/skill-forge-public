# 工程经验积累与集中交付

1. 先确认当前角色是项目记录方还是供方收集方。读取项目现行规则、活动入口和既有经验集；绑定实际项目根、唯一管理者、规则真源及部署版本，区分管理树、执行树、发布树与同名副本。通信目标按现行登记核身份，不把聊天标题或默认cwd当版本依据。

2. 项目出现已核经验、失败反例或定制需求时，更新既有条目；没有适用集合才建一个入口。为条目保留稳定ID、内容版本和摘要；只有内容变化才升版/重算哈希，供应关系变化不虚增内容版本。记录触发场景、实际规则/载荷版本、证据指针、事实层级、预期改进与未证事项。区分规则缺失、已有条款难以采用、执行误用和环境差额。需要格式时读[记录与交付字段](references/records.md)。

3. 保持项目实际使用源唯一。备选集只收可复用差额与必要来源；已有镜像按其合同单向同步，不能成为第二份独立维护正文。项目按自身授权使用和验证，不以供方收取或发版作为本地工作的前置；更新条目不追改在途冻结工单。

4. 普通积累只写本地，不逐条通知供方、不逐条请求发版。供方发起一轮定制需求收集，或用户明确要求提交时，才冻结一次交付截点。供方从本轮动态客户清单确定参与方，逐方给出收集范围、上次接收截点和回执目标；客户继续业务，准备好后异步回交，不轮询催齐、不空ACK。已影响部署、错误载荷、秘密暴露或真实业务阻断的事件沿获准渠道及时单独报告，不等批次；事故通知本身不启动整轮升级。

5. 项目交付一个批次入口：固定提交/文件摘要、相对上次截点的条目变化、实际版本与采用范围、已验证/报告/推断/失败/未测、待解决需求及不适用内容。无新增也可在该轮回一次实质结论。工作树未提交材料单独绑定物理快照，不能冒称Git版本；客户业务原件和秘密不随通用材料外发。冻结后继续积累的内容留下一批，不静默改本批身份。

6. 供方核客户指定的权威来源与实际差额，先剔除已交付、重复镜像和纯状态变化，再逐项裁定通用流程、按需示例、客户定制、保留待观察或不采用。先用已有证据回答问题，不为交材料补跑业务、故障或模型实验。接收登记不等于采用、发布、安装或效果验收。

7. 采用回执绑定条目ID、内容版本、哈希与实际Skill/版本/提交、采用及未采用范围、验证状态。客户核对真实回包后在既有登记更新关系，记录未采用理由、剩余需求与下轮触发；不另建第二客户主账。只关闭已明确解决的部分，旧失败与被替代结论保留出处。没有实质新结果不重复交付；部分客户未回只影响依赖它的裁定，不把沉默当无需求。形成候选后另走适用升级、审查、发布与部署流程，不由本技能自动授权客户写入或远端发布。
