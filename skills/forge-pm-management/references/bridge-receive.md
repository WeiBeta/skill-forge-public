# Agent-Bridge 接收

仅在项目选用此通道时读取。[接收合同](reception.md)固定终态采集、截止、预算和交接；本页补充 Bridge 的任务归属及调度。派前从当前实例发现 worker，核协调端角色、派发开关和项目对任务目录及写集的授权。worker 上下文保留防嵌套限制。接收时绑定同一实例的精确等待、状态及结果接口；接口名、分页、并发和超时按实际 schema，不能先假定存在批量等待工具（如 `wait_tasks`）。

1. **绑定。** 接收以工单中的业务任务 ID、负责的 PM、Bridge 实例、可用的稳定 request ID、期限和受理后 task/session/request 与实例映射为准。对已派任务的续等和取结果沿同 task；新派任务的标识由派发合同确定。派发回包未知时，仅按获准接口核对原请求及其实例，不盲重派。请求去重在重启后能否恢复，以实际持久化和实例恢复合同为准，未核则保留 Unknown。
2. **接收。** PM 保持接收回合，每次外层工具调用只等一个有界窗口就把控制交回 PM。支持逐单交付的并行等待时，同一窗口可收多个任务，每个 task 最多一个在途等待。保存各单返回或仍在途的等待，避免某单失败导致丢失其他结果或重复等待。工具只能串行或无法并发逐单交付时，每轮轮换一个已知任务做阻塞等待，按合同对其余任务作必要的非阻塞确认。窗口受宿主上限、剩余预算及最近相关截止约束。
3. **处理返回。** 返回 PM 后先处理暂停和新到工单，再决定是否开启下一窗口。“立即停收”即停止追加等待、确认和采集，保留现场交接。“停止新派、收完在途”只按原合同收尾。取消 worker 另按明确指令执行。获准且可隔离的插单按自己的工单派发，旧单沿原 task、截止和剩余预算续收。某单终态就按本单预算取结果、必要时按游标续取并及时回执，缺证另列。工具错误或返回不明，只在当前授权、暂停范围和预算允许时对同 task 精确核对；仍无法确定就交接 Unknown，其他不受影响的任务照常收取。
4. **保留续接。** 模型目录、实收参数、任务终态和服务生效档分别采信。共享目录变更列表仅为线索，归责或回滚先核具体写入。受理、终态和异常交接时留检查点，日常用量按[接收合同](reception.md#续等与停止线)留证。PM 或 Bridge 重启后，先确认同 task 的实例归属、原截止和已用额度；发起新等待前还须确认等待权及原等待已返回或不存在。能读取持久状态不代表可等待、取消或结束。接收期限与 worker 自身运行超时分别绑定。只按明确授权和实际终态处理专属资源，不能用结束活跃 session 代替任务终态、结果或资源释放证据。
