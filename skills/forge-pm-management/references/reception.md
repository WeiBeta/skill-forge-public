# PM 接收合同

初始化或接收能力发生变化时，将下表所需字段写入项目已有 PM 记录；工单引用该记录，只补任务自己的期限、路由等差额。工具名取自本轮实际暴露的接口，不从范本推断。

| 记录项 | 实际绑定内容 |
| --- | --- |
| 岗位与范围 | 主控、PM 实例/角色、项目根、适用授权和现场限制、负责的任务路由及不接范围。按需记录模型或模式及强度语义，自动强度按宿主合同省略字段；工具受理、执行者自报和服务身份分别取证。 |
| 通道与任务身份 | PM 类型、实际派发和接收工具、所属父回合或 Bridge 实例；业务任务 ID 与原生子 ID/turn、独立会话 ID 或 Bridge task/session/request/实例分栏，不互填。 |
| 主控通知 | 约定的实质回执渠道、目标身份、已知送达/续接方式及所依赖的权限。没有可靠自动续接证据时，指定实际可达的人工入口、记录位置与负责人；写盘或回合内结果不是跨回合通知。 |
| 累计范围 | 派前固定各单接收截止时间与时区，列宿主和工具实际允许的单次窗口、适用的累计时长/次数及最小确认间隔；先碰到任一适用上限即停。单次窗口同时满足 schema、上层硬限制及剩余预算；建议时长不能代替硬限制。实际调用计入累计，立即返回也照计；绑定可在中断后按任务恢复用量的记录。 |
| 终态采集 | 固定终态信号、结果读取与必要精确分页方法及采集预算。若允许在截止边界做一次非阻塞精确确认，派前预留并写清适用上限；没有预留则不追加。 |
| 停止与交接 | 暂停含义、允许的自然收口范围、非终态证据、已用预算与原截止、资源归属、恢复入口及下一责任人；列未满足条件和受影响动作。 |

## 按通道选择接收

| 类型 | 接收方式 |
| --- | --- |
| `gpt-native` | 在直接父接收回合内使用宿主支持的原生事件或对具体子任务直接等待。没有合法接收区间或工具时按停止线交接，不能先 `final` 再依赖原生终态自动唤醒。 |
| `third-party-subagent` | 有可靠原生事件或直接等待则使用；否则只在项目许可和累计预算内对已派的具体子任务做必要的低频等待或精确确认。按实际接口判断 V1/V2 等能力；第三方身份不决定协议。 |
| `agent-bridge` | 在合法接收回合内用本轮获准的接口拉取已派任务的结果；按 [Bridge 接收](bridge-receive.md)并行或公平轮转，落盘结果不是推送。 |

主控只等独立 PM 时，先推进输入齐备的获准工作，随后保存断点并沿已验证的实质通知机制结束回合；无可靠续接则留下人工入口，不代 PM 查状态或维持等待循环。主控获准直派原生子任务时，是该子任务的直接父会话：在回合内按实际原生工具收结果，再按职责核收，无需向自己回执；不能把这一例外扩成主控巡检。

`await` 挂起、外层工具让出、等待 timeout、父回合结束与新回合启动分别判断。无合法等待或通知能力时，保留已知事实和交接入口，只停止依赖缺失能力的动作；若新派任务依赖缺失的接收/回执路径，先不派该单。不用列表轮询、空消息、计时唤醒、无界后台 shell 或主控保活补造能力。

## 续等与停止线

- 有次数或用量上限时，按任务用可在中断后重取的工具记录恢复已用量；若无此记录，在受限调用前持久保存最小扣额（任务、动作、序号及扣额），不逐轮复制完整日志。结果未知的扣额保留；恢复工具记录与扣额不得重复计。同任务恢复原截止及已用量，必要余额无法确定时停止依赖它的调用并交接。
- timeout 是本次等待返回，并非任务终态或服务故障；仍在限额内且有合法窗口时，继续收原任务。新单、续等、回合或实例重启都不重置旧单期限或已用预算。协调等待不消耗 429/502 原实例恢复次数，也不增加业务启动次数。列表消失或文件出现不能证明终态或关闭。
- 收到具体单的终态就取其证据，按原 ID 和游标必要分页，受采集预算约束。若证据不完整，区分已知终态与尚未取得的内容，留下精确续取入口；不重启业务来补证。一单的采集不等其他单终态。
- 先处理当前暂停或拒绝。暂停涉及本单接收时，停止追加等待、状态确认和采集；只执行暂停指令明确放行的原预算内收口动作。旧合同预留的边界确认不会越过暂停，暂停指令须明确允许该确认才可继续。拒绝即停对应操作。
- 截止、预算耗尽或无合法调用区间时停止追加等待和状态确认。只有当前授权和预留额度均有效，且该确认未受暂停或拒绝限制时，才做一次预留的非阻塞精确确认。交接保留非终态、未知、已用预算、原身份/截止、资源归属和下一入口。截止或暂停不等于业务失败、取消工作或杀进程；未知是否启动时，仅在获准范围核原请求/任务，不盲重派。
