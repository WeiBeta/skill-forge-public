# 台账校对

1. 从既有恢复入口定位权威根、唯一管理写入责任人、本轮范围与核对截点。同名副本不自动代表现势，执行载体或证据提供者不自动获得主账写权；入口缺失或身份冲突时报告差异，不建并行台账。受托只读者仅交差异，由责任人核收修订。

2. 围绕活动项、最近收口和指定专项，以稳定任务ID连接：固定任务与适用批准→实际候选与证据→管理核收→当前入口/销账→下一依赖。优先复用未变化的已核固定对象，只补变化、矛盾和缺证处；不全扫历史/会话，不重跑业务证明台账。真实缺口确需状态读取时做一次有界查询，记录观察时间，不用轮询、定时器或空消息填等待。

3. 分开判断原始事实、管理裁定与现行授权。依据对象及明确覆盖关系更新；最新聊天时间或单个界面状态不能替代证据。已有适用恢复批准时更新旧暂停的现势并保留覆盖依据，不继续挂旧阻塞，也不扩大恢复授权。

4. 分别记实现、自测、独立审查、动态验证、发布和业务核收。子阶段完成不自动关闭父目标；调用受理、实际执行、终态和核收不互相代替。载体关闭不证明业务完成、进程退出或工作树可删除。失败、Unknown、NotRun、已消费次数及窗口保留来源，后续成功不抹历史或重置预算；未知只限制依赖它的动作。

5. 写前复核截点及新到的实质回执，合并仍成立的差异。唯一写入者在既有记录修正变化事实：现势错才改当前入口，补事实/依据用原专项，完成范围引用已有销账；不要求多处重复。冻结工单、原始证据和历史失败保持。纯记录修正沿已有授权，不新增业务审批。

6. 未完项保留依赖、责任与下一触发；区分尚缺管理决策和外部前置。写账失败留最小恢复点，只停依赖该记录的动作，不凭记忆重做副作用。随本轮收口核实际输入、读写范围、共享资源和汇合条件；已解除依赖且可隔离的授权工作可续接，不为填满容量制造准备任务。

7. 核本次改动的链接、固定对象和写入范围，按项目规则核工作树/提交。一次回执列范围与截点、实际差异或无差额、证据、未决与下一触发、资源和保留项。只读方不声称已修账；记录一致性不冒充业务验收、发布或宿主加载。通信、迁移、清理、模型切换和动态执行仍按原任务授权与本轮真实接口。
