# 写作与恢复案例

## 实现选择不等于授权限制

实施者把 CLI 配置入口初步写成 config，后经只读核实实际是 settings。若原授权按目的和作用范围覆盖、且不增加副作用，可在原任务内纠正并记录；若作者明确只准写 config 或禁止 settings，就不能自行替换。避免把这个例子简化为“换路径永远无需批准”。

## 历史记录与当前入口

不要在旧暂停条目下面不断叠加“最新”。历史按日期与对象保留；当前入口只留下当前授权、任务、阻塞及下一动作，链接历史。新结果解除后继依赖时检查能否推进；这属于收口动作，不是轮询或新审批阶段。

## 迁移后技能在哪

假设某项目已部署技能，但管理分支不含技能文件。入口可指向已经核验的固定 Git commit:path 供只读，不以目录缺失直接重装；缺少该对象就报告缺口。宿主可发现、人工读取、实际使用和收益验证仍是独立状态。

## 从经验到包

记录经验 ID、内容版本、全文哈希和采用范围；一条经验可以被多个技能采用，未采用部分保留。经验封装、包生成、客户部署、宿主加载及业务接纳分别记录，不预造已封装回执。

## 协调回执与工程验收

多Agent协调中，PM读取manifest后把其中哈希转述为自己重新计算，会混淆证据来源。回执分清执行者报告、协调者实查和主控验收；可靠计数直接引用结构化字段，无证填Unknown。PM默认核完整性，额外工程检查由工单明确，避免多层重复审计。范围偏差准确标记，不能以最终成功冲淡原失败或删除事实。此案例不要求所有文档任务增加一名PM。
