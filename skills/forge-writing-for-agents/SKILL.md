# 代理文档与交接

先确定谁读、何时读、读后需要作什么判断。正文保留共有约束；分支资料按“触发→入口→预期判断”引用。使用已有治理、知识与台账，不另建并行真源。稳定规则与任务状态分开。短入口只指向现行权威、活动事项与下一依赖；事实写在已有记录，按稳定ID或固定对象引用，保留历史和明确的覆盖关系。

结构化交付面对真实消费者：引用现有 schema 或真实样例，说明晚生成身份在哪里产生、何时注入；交付前做最小离线契约核对，不靠自然语言猜字段。普通文档不因此增加机器可读框架。

恢复入口必须可达。首次接管或规则整体变化时读完整协议，日常续接按活动项取需要的规则与证据。技能物理文件缺失时，先确认实例和已绑定部署对象，再只读回取；不猜旧版本、不自动安装或同步其他树。备份清单读取失败不能当成 0 项通过。

完成条件区分候选、审查、运行验证、发布、加载和业务接纳。更新当前入口时检查“新回执已解除哪些后继依赖”，按输入、写集和共享资源判断可推进任务；不为这一步新增定时检查或重复审批。主账由管理单写，阶段完成不能代替父目标完成。

审批按真实副作用增量判断。工程上暂定的文件路径不是作者硬上限；若路径确是作者冻结限制，则仍服从该合同。已授权范围内的实现纠正不逐字段重批，新秘密访问、外发、不可逆影响等按适用权限处理，不复制客户的具体授权进通用 Skill。

收尾检查每条新增规则解决了哪次判断，链接是否可达、哪些旧入口被替代。优先删重复回读与脆弱步骤，不因一次执行遗漏再加同义制度。需区分授权措辞或记录时态时读[写作案例](references/cases.md)；来源见[归属](references/attribution.md)。
