# 路线 B：OpenCodex 可选参考

需要额外的模型路由层时，可用此页设计验证。原生用户从[路线 A](../codex-native/README.md)开始。此处不提供第三方 Provider 安装器、现成凭据或可以照抄的模型目录。

[wait-v2.example.toml](wait-v2.example.toml) 是版本化的历史配置参考：Codex core 0.167.0-alpha.3.2 与 OpenCodex 2.98.0，模型级选择协议，全局 V2 保持关闭。该文件只展示 Codex 侧的实验等待字段，不定义 OpenCodex 的配置接口。其他版本、路由和模型组合需要另核。公共发行未实测该组合，也没有认定原生或第三方路线的默认协议或性能。

1. 从自己的可信安装来源核目标核心、OpenCodex 版本、模式和模型目录；只列允许变更的字段并另存原配置。
2. 在目标环境核实际可用模型、工具 schema 和参数。不要把 V2 等待参数当作 V1 路径的生效配置。
3. 用一项无业务副作用的任务记录请求受理、实际路由证据、等待、回执和资源关闭。模型自报或路由标签不能独立证明供应商内部模型身份。
4. 验收失败时保存证据，分开判断权限、容量、限流、包装器和业务结果。只在已获准的环境按实际差额恢复配置。

更多边界见[运行合同](../../docs/RUNTIME-CONTRACT.md)和[验收指南](../../docs/VALIDATION.md)。
